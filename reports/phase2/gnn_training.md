- Across each training epoch, exactly **63,621 valid labels** are processed out of 75,096 total potential entries (representing an observed label density of 84.72% across the 12 endpoints).

$$\mathbf{Z} = \text{MolecularGNN}(\text{batch}) \in \mathbb{R}^{B \times 12}$$
- The output consists of raw, unbounded prediction logits $\mathbf{Z}_{b, t}$ for each graph $b \in \{1, \dots, B\}$ and toxicity task $t \in \{1, \dots, 12\}$.

- Tensors are automatically verified to be on the model's compute device, finite, and strictly free of NaNs.

## 4. Masked Multi-Task Binary Cross-Entropy Formulation

### 4.1 Theoretical Foundation
Tox21 multi-task learning presents significant missingness because individual chemical assays were tested against different subsets of the 12 targets. Computing a conventional loss across all entries would backpropagate garbage gradients from unmeasured endpoints or arbitrary NaN imputations.

Let $y_{b, t} \in \{0, 1\}$ be the true binary toxicity label for molecule $b$ and endpoint $t$, and let $m_{b, t} \in \{0, 1\}$ be the binary mask indicating whether assay result $(b, t)$ is observed and valid:
$$m_{b, t} = \mathbb{I}(y_{b, t} \text{ is not NaN} \land \text{mask}_{b, t} = \text{True})$$

Let $z_{b, t} \in \mathbb{R}$ denote the predicted logit. For numerical stability, targets $y_{b, t}$ containing NaNs are masked prior to computing the cross-entropy:
$$\tilde{y}_{b, t} = \begin{cases} y_{b, t} & \text{if } m_{b, t} = 1 \\ 0.0 & \text{if } m_{b, t} = 0 \end{cases}$$

The elementwise binary cross-entropy with logits $\ell_{b, t}$ is:
$$\ell_{b, t} = \max(z_{b, t}, 0) - z_{b, t} \tilde{y}_{b, t} + \log\left(1 + e^{-|z_{b, t}|}\right)$$

When positive class weighting $w_t > 0$ is applied, the loss becomes:
$$\ell_{b, t}^{(w)} = \left(1 - \tilde{y}_{b, t}\right) \log(1 + e^{z_{b, t}}) + w_t \tilde{y}_{b, t} \left[\log(1 + e^{-z_{b, t}}) - z_{b, t}\right]$$

The multi-task masked loss $\mathcal{L}_{\text{masked}}$ averaged over all valid endpoint observations in the minibatch is:
$$\mathcal{L}_{\text{masked}} = \frac{\sum_{b=1}^B \sum_{t=1}^{12} m_{b, t} \cdot \ell_{b, t}}{\max\left(1, \sum_{b=1}^B \sum_{t=1}^{12} m_{b, t}\right)}$$

### 4.2 Numerical Verification & Edge Cases
The loss implementation in `src.training.losses.masked_bce_loss` was validated across 8 unit tests:
1. **Zero Valid Labels:** If an entire minibatch contains only missing values ($\sum m_{b,t} = 0$), the function returns a tensor of `0.0` with gradients attached rather than throwing a division-by-zero or NaN error.
2. **Missing Label Isolation:** Perturbing the value of a masked entry ($y_{b, t}$ where $m_{b, t} = 0$) causes exactly zero gradient change to the model parameters ($\nabla_{\theta} \mathcal{L} \equiv 0$).
3. **Multi-Task Invariance:** Independent endpoints do not interfere with each other's loss contributions.

## 5. Class Imbalance Mitigation & Positive Class Weighting

### 5.1 Endpoint Imbalance Characteristics
Tox21 endpoints exhibit severe positive class sparsity, ranging from ~3.5% positive labels (SR-HSE, NR-PPAR-gamma) to ~15.5% (NR-AR-LBD). 

To prevent the neural network from trivializing predictions toward the majority negative class, `src.training.losses.compute_endpoint_pos_weights` calculates endpoint-specific positive weights $w_t$:
$$w_t = \min\left(\frac{N_{\text{neg}, t}}{N_{\text{pos}, t}}, w_{\text{max}}\right)$$

Where:
- $N_{\text{neg}, t}$ is the count of negative samples for endpoint $t$ in the training set.
- $N_{\text{pos}, t}$ is the count of positive samples for endpoint $t$ in the training set.
- $w_{\text{max}} = 50.0$ is an upper clamp to prevent exploding gradients on rare endpoints.

### 5.2 Training Configuration Control
Positive weighting is made configurable via `TrainingConfig(use_pos_weights=True/False)`. In standard cross-entropy evaluation, `use_pos_weights=False` optimizes raw calibrated probabilities for ROC-AUC ranking, while `use_pos_weights=True` shifts the decision threshold to favor sensitivity/recall on imbalanced screening tasks.

## 6. Optimization Architecture & Hyperparameters

The optimization framework is designed for rapid convergence, stability under deep message passing, and smooth gradient flow:

| Component | Setting | Scientific Rationale |
| :--- | :--- | :--- |
| **Optimizer** | `AdamW` | Decoupled weight decay regularization prevents over-parameterization without corrupting adaptive moment estimates. |
| **Initial Learning Rate** | `1e-3` | Standard optimal learning rate for graph neural message passing with LayerNorm. |
| **Weight Decay** | `1e-4` | Moderate L2 weight penalty for generalization control. |
| **Gradient Clipping** | `1.0` (max norm) | Prevents gradient explosion in recurrent-like edge message passing across deep molecular rings. |
| **LR Scheduler** | `ReduceLROnPlateau` | Multiplies learning rate by factor $0.5$ when validation loss ceases to improve for 4 consecutive epochs (`scheduler_patience=4`). |
| **Minimum Learning Rate** | `1e-6` | Prevents learning rate from vanishing prematurely before convergence. |
| **Minibatch Size** | `64` graphs | Balances GPU/CPU vectorization with gradient variance across diverse molecular scaffold topologies. |

## 7. Validation Strategy & Early Stopping Policy

### 7.1 Leakage-Free Validation Loop
Validation is evaluated strictly at the end of each epoch over `datasets["val"]` without gradient computation (`torch.no_grad()`). The test partition (`datasets["test"]`) is never loaded into memory during the optimization loop, guaranteeing absolute zero data leakage.

### 7.2 Early Stopping Protocol
`EarlyStopping` (`src.training.early_stopping.py`) monitors validation loss $\mathcal{L}_{\text{val}}$:
- **Patience ($P$):** 7 to 10 epochs.
- **Minimum Delta ($\delta$):** 0.0 (any non-improving epoch increments the counter).
- **Best Model Criterion:** If $\mathcal{L}_{\text{val}}^{(e)} < \mathcal{L}_{\text{val}}^{\text{best}}$, the model weights are checkpointed to `best_gnn.pt` and the counter resets to 0.
- **Termination:** If the counter reaches patience ($C \ge P$), training terminates immediately, preserving the best epoch's weights.

## 11. Reproducibility & Cross-Platform Support

### 11.1 Random Seed Control
Deterministic execution across environments is guaranteed by `set_seed(seed)` in `src.training.reproducibility.py`:
- Python standard library `random.seed(seed)`
- NumPy `np.random.seed(seed)`
- PyTorch CPU `torch.manual_seed(seed)`
- PyTorch CUDA `torch.cuda.manual_seed_all(seed)`

### 11.2 Hardware Device Fallback
The `get_device(preference="auto")` utility supports:
- **NVIDIA CUDA:** Automatically selected when `torch.cuda.is_available()`.
- **Apple Silicon MPS:** Supported on macOS 15+ environments.
- **CPU:** Standard vectorized fallback providing 100% deterministic, cross-platform behavior.
